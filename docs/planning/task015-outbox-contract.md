## Proposed transaction/replay protocol

Executor accepts only server-selected registered operation/validated normalized input/current verified actor+session, UUID key and side-effect-free Mongo mutation callback. HTTP authorization is always performed fresh BEFORE any replay, using TASK-006 current authority and current open session; replay cannot bypass later role restrictions. Callback uses only the supplied Content Mongo session, sequential writes and approved business guards. No provider/HTTP/file side effect in a transaction callback because it may be retried.

Canonical hash covers operation, target identifier and normalized request body; recursively sort object keys, preserve array order and types, reject nonfinite/undefined/non-JSON data. No JWT, transport requestId or current session in hash: a valid retry after reopening a session replays the original committed session/event. Actual endpoint-specific normalization stays in later API contracts. Never persist the raw canonical request. Same actor+operation+key with changed hash returns409 IDEMPOTENCY_CONFLICT. Key scopes include target in the hash, so it cannot be reused for another POI under the same operation.

New request: in one transaction insert in_progress, execute callback, insert strict immutable outbox event(s) and complete replay record with minimal result; commit all together. No standalone reservation commit. Callback cannot commit a successful content mutation without its required audit intent. UUID event IDs and occurredAt/context are fixed for the logical transaction attempt and retained across driver retry. Failure before commit aborts all. Do not cache validation/auth/conflict/dependency failures as success. No out-of-transaction network send during commit.

Concurrent identical requests converge on unique actor/operation/key: after duplicate/contention, reread durable record and replay completed result; no independent second callback outside a new guarded transaction. Maximum3 application attempts; exhausted/uncertain returns503 MUTATION_UNAVAILABLE. Driver handles commit retry under a total10s transaction budget, with majority write concern/primary reads; budget expiry does not prove rollback. After ambiguous commit, reread completed record before any future execution; unique index+transaction ensure pending commit cannot silently duplicate the same key. Tests must cover commit success with lost response.

Replay completed record while now<expiresAt returns original responseStatus and minimal body, with a fresh outer requestId; no new mutation/outbox, and no rewriting original actor/session/time. Exactly at expiry replay guarantee ends: delete that completed record and create replacement only inside the same guarded transaction; a different hash remains409 while the old record is present and unexpired. Business state/version validation is mandatory even after expiry; a new key/expired key is not a permanent deduplication guarantee.

New executor never durably leaves in_progress because reservation/completion commit together. If a pre-existing durable in_progress is observed, regardless of expiry, fail closed503 IDEMPOTENCY_RECONCILIATION_REQUIRED; never auto-delete/reexecute it. Inspect only Content-owned completion/business evidence; no guessed outcome or arbitrary callback recovery. This task exposes a diagnostic classification, not an operator endpoint or automatic repair tool. Safe remediation requires separately authorized, evidenced reconciliation. Test restart preserving this quarantine. No TTL may erase ambiguous state.

## Proposed outbox delivery

Reuse IDENTITY_BASE_URL and CONTENT_IDENTITY_SERVICE_KEY_B64URL validation from TASK-006; exact origin HTTPS in production, loopback HTTP only dev/test. POST /api/v1/internal/audit-events with existing scoped headers, original payload, no browser JWT/Origin. Total HTTP deadline3000ms includes body; redirect forbidden, response maximum16KiB. Only201/200 with strict TASK-008 acknowledgement matching eventId and canonical receivedAt confirms delivery. Validate requestId envelope; malformed/wrong-ID response,409,401/403,422,429,5xx and network/timeout leave pending. Never rewrite payload or generate a new eventId to escape409.

One in-process sender, one request at a time; each scan selects one due undelivered event ordered nextAttemptAt then _id. Empty queue polls at most once/second while service is awake. No distributed lease/new fields: multiple processes may deliver duplicates; receiver unique eventId makes effects idempotent, not exactly-once or globally ordered delivery. Mark deliveredAt=server acknowledgement time via conditional update only when still null. A losing concurrent failure must not reset delivered state. attemptCount advances with a conditional update before the request, safe-integer bounded; exhaustion at numeric maximum retains pending and reports safe diagnostic rather than wraps.

Failure delay uses approved5/10/20/40/60seconds then cap60, plus uniform jitter0–20% of base; deadline is server now+delay, no immediate retry loop. Conditional attemptCount updates prevent an older failure overwriting a newer schedule. A crash after attempt increment but before HTTP leaves event pending for next startup; crash after receiver commit before local acknowledgement replays same eventId. Poison records do not block other due events: retain safe failure classification without adding a DB field, continue after scheduling retry. Logs/callback diagnostics contain stable codes/counts/requestId only, never bodies/credentials.

Explicit start runs due recovery then polls; stop cancels future polls, aborts active fetch and awaits the bounded active work. Tests inject clock/random/fetch, not real sleep/backoff or a production timer. No claim of scheduling while Render sleeps. No product bootstrap connection/secret consumption is enabled automatically by importing this module.
