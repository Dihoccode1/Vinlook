## Content transport and lease

Use existing `/api/v1/internal/jobs/claim`, `/:id/renew`, `/:id/media-intents`, media file/reconcile and result APIs, with existing X-Vinlook-Worker-Id/Key headers. Content origin fixed by config; no redirects, environment proxy forwarding, arbitrary URL or disabled TLS checks. Validate response requestId/data/enums/canonical IDs/attempt/version/snapshot shape and byte caps; reject unknown privilege-bearing fields. JSON cap 128 KiB, ordinary request deadline 15 seconds; upload deadline 100 seconds around Content's existing 90-second limit. Errors expose only safe codes, not raw response/text/header/stack.

After claim, persist job/attempt/inputHash before starting synthesis. Renewal runs in the parent independently of the CPU child, every 60 seconds; never wait for inference to finish. Keep existing five-minute lease and max-three server reclaim semantics. Failed/ambiguous renew causes immediate child cancellation and stops upload/new side effects; no optimistic continuation until lease ownership is reconfirmed. Whole local job limit 600 seconds, synthesis child limit 480 seconds and FFmpeg/probe limit 20 seconds each. Backend limits remain unchanged. Abort on stale source/text/draft/deletion, expired/lost attempt or credential denial.

A lost claim response cannot be safely replayed: stop with CLAIM_ACK_UNKNOWN, do not immediately claim another job. Keep a local uncertainty marker and wait at least the original five-minute lease window before an explicit later run may claim again. No new backend claim-idempotency schema is introduced here. Old lease expiry is not proof of provider/media rollback.

## Synthesis and MP3 validation

One job and one model-loaded child at a time, CPU inference/eval, four Torch threads, fixed seed 42 for research repeatability rather than a bit-identical speech promise. Model child inherits no worker/network credential, uses only bounded local inputs and cache, and exits after the job to release memory. Parent renews lease and samples resource use. Reject missing/incompatible cache/model/tokenizer before inference. Tokenizer's required uroman preprocessing changes pronunciation input only, never the stored narration text/version. Track normalization/profile metadata locally; locale quality remains human-reviewed.

Split long text deterministically at whitespace after sentence punctuation including .!? and script equivalents, then whitespace where necessary; preserve original substrings/order, no summarization or text deletion. Maximum chunk 400 Unicode code points and 256 tokenizer tokens, maximum 64 chunks; unsplittable over-limit input fails safely. No arbitrary split inside a word/script token as a hidden quality fix. Bound each generated finite mono signal; stop once aggregate PCM exceeds 150 seconds or 16 MiB. Concatenate directly without inserted silence; reject empty/nonfinite/all-silent/overlong/under-90-second output. No automatic rate adjustment, cropping, padding or transcript rewrite.

Model's configured sample rate is authoritative after strict supported-range validation (8–48kHz); do not mislabel MMS 16kHz output as Gemini 24kHz PCM. Convert PCM16 mono to MP3 mono/24kHz/64kbps with pinned FFmpeg, one thread, shell:false, fixed pipe-only format/args and bounded stderr/stdout. FFprobe independently requires MP3/mono/24kHz and duration 90–150 seconds, bytes <=3 MiB; Content TASK019 validation remains authoritative. Encoder frame padding can push borderline 150-second PCM outside the MP3 bound: reject, do not silently edit narration. Expose a safe failure for Staff to revise text/manually retry through existing APIs.

## Durable local recovery and upload boundaries

Private state volume contains bounded typed JSON journal and at most the current attempt's WAV/MP3. Job/attempt-based server IDs form paths; resolve/canonicalize under state root, reject symlinks/traversal/unexpected files, atomic same-directory write + fsync + replace. No key or raw provider error in state. Journal binds jobId/attemptId/inputVersion/inputHash/registry/profile, phase, file digests and nullable mediaIntentId/exact result body. State is private narration data, never web-served. Proposed one live attempt, <=32 MiB per-attempt storage; retain uncertain state and refuse new work until resolved rather than evicting evidence. Remove only that validated completed/stale attempt's temporary files; retain a small bounded safe completion receipt. No recursive arbitrary cleanup.

Persist phases before nonrepeatable operations: claimed, synthesizing, mp3_ready, intent_requesting, intent_known, upload_started, result_pending, completed/blocked. Recovery verifies digest and reacquires the same unexpired lease via renew before continuing any synthesis/upload. If lease is lost or attempt changed, stop and discard no remote evidence; do not attach/relabel old media to a new attempt. Local synthesis can restart only with a live renewed attempt, because it has no cloud side effect. MP3 may be reused only with matching original job/attempt/hash and verified digest.

Persist intent_requesting BEFORE POST. If creation acknowledgement is lost, no intent ID is known: do not issue another intent automatically. Retain blocked state and submit a safe failure only if the original attempt is still live; human resolves/retries. Existing server API offers no worker lookup by request key; this limitation is explicit, not a fabricated recovery query.

Persist upload_started BEFORE first PUT. Lost/ambiguous upload response: only call existing reconcile for the known intent, never repeat PUT. Reconcile can return unavailable while Content still considers its 90-second upload in progress: retain state and retry read-only reconciliation on a later explicit/active run with a live lease. At most three reconciliation attempts per run, backoff 5/15/30 seconds within the whole-job/lease budget, then stop blocked. No re-synthesis merely to recover Cloudinary acknowledgement. Keep remote media and existing audit history intact.

Persist exact result_pending body before POST. Lost acknowledgement permits at most three identical result POSTs per run, because TASK016 receipts make matching job/attempt/body replay safe. Try this receipt replay before renewing during recovery: a completed receipt can validly return after lease expiry; a stale/conflicting attempt stops. Never change result payload or attach a different intent to the same receipt. Normal failures use existing PROVIDER_FAILED outcome; no new Content status/schema/auth endpoint is proposed. Human Staff retry remains the server policy; worker never calls admin retry or publishes content.
