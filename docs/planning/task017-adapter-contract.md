Caps must come from an explicit later review of the actual project free tier; this contract does not invent account limits. No automatic account inspection, paid tier, alternate key or quota expansion. App counters cannot guarantee provider billing status.

Propose `POST /api/v1/admin/jobs/run-next` with strict empty JSON and UUID Idempotency-Key; fresh Staff/Manager and open work session, existing CORS/no-store/requestId conventions. It admits one server_adapter job and returns 202 with jobId/attemptId, or 200 with null if none. Replay returns the original admission without another runner. One process slot plus a durable singleton dispatch lease prevents overlapping adapter execution across replicas. Busy returns 409 ADAPTER_BUSY. No timer that wakes Render; another explicit request advances the queue. TASK018 worker cannot claim server_adapter work. Admission starts a bounded asynchronous task in the current process; a process exit may interrupt it and must be handled by durable recovery below. This is a prototype execution trigger, not a delivery guarantee or a new public user endpoint.

Renew existing job lease every 60 seconds during an admitted task; maximum whole task 300 seconds. Recheck attempt and input admission before each provider/upload/result boundary; stop after lost lease, stale draft, deletion or shutdown. Preserve original requesting actor/session for completion audit. No external request inside a Mongo transaction.

## Durable dispatch and quota amendment

Add strict Content collection `provider_calls`, no TTL, auto-create/index or raw provider payloads. Fields: jobId, retryCount, attemptId, registryVersion, taskType, modelId, requestHash, state (`reserved|dispatched|completed|failed|uncertain`), reservedAt/dispatchedAt/finishedAt, safe errorCode, nullable mediaIntentId/resultHash; server-owned IDs/dates and bounded identifiers. Unique (jobId,retryCount) prevents two POSTs for one retry cycle. Additional index (state,dispatchedAt). Store no key, prompt duplicate, WAV or base64. Amend owned catalog explicitly; missing collection/index disables adapters without auto-provisioning Atlas.

Add strict `provider_controls` collection with singleton execution lease and per-model minute/day counters, unique control key and bounded typed counter/lease fields. Reservation, dispatch marker and quota reservation use Mongo transactions/CAS. Count conservatively before dispatch; never refund an ambiguous request. Use rolling minimum spacing plus UTC-day counters for application limits, documented as conservative local controls rather than Google's quota-reset model. 429 requires manual retry and provider cooldown; local quota exhaustion produces waiting_quota without POST. No automatic retries for any provider HTTP/network failure.

Write dispatched marker durably BEFORE the single provider POST. A timeout, disconnect, malformed/truncated successful response or crash after that marker is uncertain. On restart or job lease reclaim, a dispatched/uncertain row forbids another POST; fail the job with safe `PROVIDER_OUTCOME_UNKNOWN`. Add this error enum to job reads/result handling. Even a crash between marker and send is treated conservatively; exactly-once computation is not claimed. An expired reserved row with no dispatch marker can be acquired safely after prior runner lease expiry. Completed translation receipt and accepted job result must commit atomically; late duplicate responses cannot overwrite newer content.

Extend existing retry body only for unknown outcomes: `{expectedEditVersion, acknowledgeProviderResend:true}`; reject missing acknowledgement with 409 PROVIDER_RETRY_CONFIRMATION_REQUIRED. Ordinary retry keeps its existing shape. Each explicitly accepted retry increments retryCount and retains prior ledger/audit evidence. A new call may consume quota or duplicate provider computation; display the safe reason in admin job read. Retry remains an explicit human action and never a publication action.

For audio, persist mediaIntentId before upload; if Cloudinary acknowledgement is uncertain, recovery only reconciles that intent. Do not synthesize again to recover an upload. If a verified intent survives, resume job result using the existing attempt-bound rules; no attachment under a different attempt. If transient WAV/MP3 was lost before upload, fail conservatively and require the explicit acknowledged retry above. No pretend durable audio receipt.

## Provider transport and output

Use native fetch, fixed HTTPS Google host, no redirects, SDK retries or caller URL. Translation uses the supported generateContent REST structured-output endpoint; TTS retains the research `/v1beta/interactions` endpoint with audio response and `store:false`. API key only in header, never query/log/error. Request hash binds exact task, locale, input version, registry/profile and prompt. Narration/source text is untrusted data, never an instruction, tool call or URL to fetch.

Translation requests one target locale per call and strict JSON `{languageCode,text}` schema. Parse exactly that object, matching locale, nonempty text <=20000 UTF-16 units; reject extra fields, refusals, tool calls and incomplete/multiple candidates. Do not claim semantic quality from schema validation. Timeout 90 seconds and response cap 128 KiB. No automatic shortening, summarizing or modifying the English source.

TTS reads exact current locale transcript with frozen profile/style; nonstreaming single audio response, timeout 150 seconds, JSON body cap 12 MiB and decoded WAV cap 8 MiB. Require one unambiguous audio output, audio/wav, strict base64 and actual RIFF/WAVE PCM16 little-endian, mono/24kHz, finite duration 90–150 seconds and nonzero samples. Reject malformed chunks, compressed/unsupported formats or mismatched bounds. A shorter research sample does not satisfy production narration acceptance. Do not pad, crop, speed up or silently request synthesis again.

FFmpeg spawn uses argument array, shell:false, no inherited cloud secrets, stdin WAV/stdout MP3, bounded stderr and output, 20-second deadline, one thread, no network/protocol input or user filesystem path. Profile mono 24kHz libmp3lame 64kbps. Independently probe and reuse TASK019 validation: MP3 <=3 MiB, mono and 90–150 seconds. No transcript-based filenames or intermediate public files. Kill child and close streams on abort; no unbounded buffering. Cloudinary upload retains its existing one-slot/90-second limits and result provenance checks.
