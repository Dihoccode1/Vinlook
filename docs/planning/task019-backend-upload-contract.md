## Proposed bounded ingestion/probe

Authenticate before reading request body. Exactly one multipart file named file, no text fields, extra files/parts rejected; ignore client filename/path/MIME as evidence. Limits use binary units: input thumbnail<=2,097,152bytes, input audio<=3,145,728bytes, total multipart<=file limit+65,536bytes. Abort oversized/chunked overflow, malformed/truncated multipart and request disconnect. Stream with backpressure into a bounded in-memory buffer; no media written to public/temp disk. One active upload per Content process, no waiting queue; busy503 UPLOAD_BUSY/Retry-After5. This is per-process capacity, not a distributed lock/global rate limit.

Thumbnail only JPEG/PNG/WebP, positive dimensions<=1600each, one still image (reject animated/multipage/SVG/HTML/other formats). Bound Sharp input pixels to2,560,000; full decode, apply orientation, strip metadata and encode canonical WebP quality90, dimensions unchanged except orientation. Canonical output must also fit2MiB. Preserve actual canonical SHA256/bytes/dimensions. No silent resizing of an over-limit image. This canonical output choice is newly proposed, not a requirement already implemented.

Audio only MPEG LayerIII MP3 with all frames mono, finite calculated duration90–150seconds inclusive. Read complete bounded bytes, handle bounded ID3 tags (aggregate<=256KiB), reject malformed/truncated/trailing non-tag data or inconsistent frame channels/rates; compare frame-derived duration to parser duration with tolerance0.1s. VBR allowed if valid;64kbps remains a target rather than an invented hard requirement. Record measured bitrate; do not claim parser validation proves intelligible narration. Audio is not transcoded on Render; existing local pipeline must supply compliant MP3. Preserve input bytes/SHA256. No accepting duration/channels from caller alone.

Per request total90s after authorization: body receive<=30s, binary probe<=5s, Cloudinary upload<=30s, authenticated metadata check<=10s, original CDN byte read<=10s, remaining DB work within total budget. Deadline/disconnect cancels streams/HTTP/probe; cancellation does not prove provider rollback. Native image probe runs in a terminable worker so a Promise timeout cannot pretend CPU work stopped. Audio parser also isolated/bounded. Tests measure bounded behavior; no free Render performance/cold-start promise before deployment measurement.

## Proposed durable MediaUpload model

New Content collection media_uploads, strict typed schema/nested allowlists, ObjectId _id, versionKey=false, no autoCreate/index/buffer. Fields:
- uploadId canonical UUID; kind thumbnail|audio; poiId/revisionId logical Content ObjectIds; jobId nullable ObjectId (audio required, thumbnail null).
- actorId/workSessionId logical verified original Identity IDs; expectedEditVersion safe integer>=0; sourceVersion/textVersion nullable safe integers>=1 (audio required); languageCode/registryVersion/voiceOrModelId nullable exact registry-bound strings (audio required, thumbnail null).
- publicId server-generated vinlook/{development|test|production}/{poiId}/{revisionId}/{thumbnail|audio}/{uploadId}; resourceType image for thumbnail, video for audio; format null until probe then webp or mp3. Caller cannot supply publicId/resourceType/namespace/provider URL.
- status issued|uploading|verified|rejected|uncertain; createdAt UTC server Date; expiresAt=createdAt+15minutes; startedAt/finishedAt/attachedAt nullable UTC Date; safeErrorCode nullable allowlist INVALID_MEDIA,UPLOAD_FAILED,UPLOAD_UNCERTAIN,STALE_INPUT,DEPENDENCY_UNAVAILABLE. No raw error/body/credentials.
- sha256 nullable lowercase64hex; bytes nullable safe positive integer; width/height nullable safe positive integers; durationSeconds/bitrate nullable finite positive numbers; providerVersion nullable safe integer>=1; providerAssetId nullable bounded nonempty string; url nullable canonical credential-free HTTPS; all fields conditional by kind/state. No arbitrary JSON/Mixed or binary in DB.
Indexes unique(uploadId), unique(publicId), compound(status,createdAt); no TTL/deletion of history/orphans. No claim1record means1successful provider asset. Exactly15minute local admission is backend-controlled; Cloudinary signatures still have underlying1h validity but never leave backend.

Intent starts issued. CAS issued->uploading sets startedAt and accepts bytes only before expiresAt, with fresh current actor/session/revision/version check. Persist probed digest/metadata BEFORE provider request; if this persistence fails do not call provider. Invalid file->rejected, no provider request. A known definitive rejection retains rejected; a timeout/disconnect/unknown provider outcome->uncertain. Crash may leave uploading. No automatic second provider POST for any uploading/uncertain record: read-only reconciliation first. Exact same intent/file retry after verified may return stored reference after fresh authority and digest match; changed bytes409 MEDIA_INTENT_CONFLICT. New media after rejection needs a new intent/public ID. Permanent uploaded/verified refs do not expire merely because the15minute admission window ended.

## Proposed staff endpoints

Prefix /api/v1; exact Content origin allowlist/no-store/current Staff or Manager/shared workspace. Mutating routes require current open session; uploader must own intent (Manager has no arbitrary impersonation override). Status read is workspace-readable, no open session required; return only safe metadata/IDs, no secret/signature/internal request body.

POST /admin/revisions/:id/media-intents — strict JSON16KiB {expectedEditVersion,kind:thumbnail}; validate parent not deleted, revision draft/version current; create one issued intent and201 {data:{intentId,status,expiresAt,uploadPath},requestId}. No provider call or POI mutation on intent creation. No idempotent response claim: retry after losing this response can create an unused intent, which costs no provider upload and is retained. Technical intent itself records actor/session; actual content attachment is audited by existing poi.update action, no new audit action invented.

PUT /admin/media-intents/:id/file — one bounded multipart file above, current original actor and open original session; revalidate bound parent/draft/expectedEditVersion before admitting. Return201 verified {data:{intentId,status,asset},requestId}; asset strict TASK011 thumbnail shape. No automatic POI attachment or hidden version increment. Client then PATCHes revision with expectedEditVersion and this asset, using existing atomic business audit. Stale403/409 states admitted before provider call consume no upload. If edit/source/delete changes while provider request is in flight, retain result as unattached; it cannot overwrite new content. Verified same-byte replay200; uploading/uncertain409 MEDIA_RECONCILIATION_REQUIRED; stale/expired409 MEDIA_INTENT_EXPIRED or EDIT_VERSION_CONFLICT; body/format400/413/415/422; capacity/dependency503. No arbitrary client provider URL or duration accepted.

GET /admin/media-intents/:id —200 safe intent status plus verified asset or null, bounds/safe failure code/original IDs/times; no provider request on an ordinary status read. Missing/nonowned upload mutation404; read shared existing intent allowed, no raw provider payload.

POST /admin/media-intents/:id/reconcile — strict empty JSON object, fresh owning actor+current open session. Only uploading/uncertain or verified record; query authenticated provider metadata and bounded exact original bytes, no new upload/no delete. Verified same digest/version/namespace ->verified; absence/error/unknown stays uncertain with safe response503, not proof that it is safe to retry same public ID. Reconciliation can finish an admitted upload after intent expiry without admitting new bytes. Old session retained as provenance; current permission does not rewrite original actor/session. No timer automatically invokes reconciliation or deletes assets.

## Proposed Cloudinary adapter/config

Opt-in private CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET all required as a set for media runtime. Cloud name restricted alphanumeric/underscore/hyphen, exact provider account; API key/secret nonempty bounded strings, no URL control characters. No secret in log/config serialization/client/worker/Docker image/repo. Missing config leaves existing nonnull thumbnail input safely unavailable503, not a fake verifier. Enabling config does not trigger a live upload/probe at startup.

Use Node built-in fetch/FormData/crypto and fixed https://api.cloudinary.com/v1_1/{configuredCloud}/{image|video}/upload, SHA256 signature of sorted fixed upload params plus API secret; timestamp server Unix seconds, public_id server record, overwrite=false,type=upload. Provider credentials and signature stay only on outgoing backend request. No upload preset/eager transform/folder/remote URL caller options. No automatic retry, redirect or paid fallback. Bound all provider JSON response bodies64KiB; timeout/status429/5xx/auth errors map to safe dependency states without echoing internals.

Independently read configured account's authenticated Admin resource endpoint for expected resourceType/type/publicId; verify returned publicId/version/assetId/format/bytes/dimensions or duration against the intent. Do not accept returned arbitrary secure_url. Construct only exact untransformed HTTPS res.cloudinary.com/{cloud}/{resourceType}/upload/v{version}/{knownPublicId}.{format}; no custom host/query/fragment/redirect. Fetch original bounded bytes (same<=2/3MiB) and compare SHA256 to the persisted canonical/input digest, then binary metadata constraints. If Cloudinary/account processing changes bytes unexpectedly, fail closed rather than silently accept. Unknown provider outcome never triggers a duplicate upload. Account admin/credential access is trusted but not a defense against out-of-band provider account owners overwriting/deleting assets; later publication rechecks remain mandatory.
