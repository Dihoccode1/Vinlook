POST /api/v1/admin/revisions/:id/media-intents accepts {expectedEditVersion,kind:thumbnail}; PUT /api/v1/admin/media-intents/:id/file accepts one multipart file; GET same intent path returns safe status/metadata; POST /reconcile accepts {} and only performs provider reads. Only original actor uploads/reconciles, with shared status visibility; audio is not exposed as a browser upload. See approved docs/planning/task019-backend-upload-contract.md for exact states and limits.

Workflow: create POI draft with thumbnailAsset=null, issue intent, upload through backend, then PATCH existing draft with verified canonical ref and expectedEditVersion. Nonnull initial create returns422 MEDIA_INTENT_REQUIRED. Verified refs are restricted to the same POI; clone can reuse immutable prior refs. First attachedAt is written with content/outbox in the same transaction, so a conflict/audit failure leaves a verified asset unattached. Upload alone does not advance content version or publish anything.

One process-wide active upload slot, no waiting queue; busy503 Retry-After5. Bounded multipart input and transport drain on rejection; no client MIME/path trust. Input thumbnail<=2MiB, MP3<=3MiB, total multipart<=file maximum+64KiB. Native image/full MP3 probe runs in a terminable child with5s deadline. Parent gives it only bounded bytes and OS runtime environment, explicitly clears inherited execArgv (including --env-file) and excludes provider/DB/service/JWT config. No temp media files. Full image decode/orientation/metadata strip emits WebP quality90; full MP3 frame scan/parser verifies mono and90/150 inclusive sample-derived duration. This is structural validation, not narration quality approval. Local worker still supplies compliant MP3; no backend FFmpeg download/transcode.

Durable MediaUpload issued->uploading persists canonical digest/metadata before provider POST. Uploading/uncertain never triggers a second automatic POST. If timeout/cancellation prevents even the terminal DB write, uploading remains a durable ambiguous state and is reconciled after its90s admission window. A15minute local intent admission limit is not Cloudinary signature TTL. Cloudinary request credentials/signature never leave backend. Verified same-file retries may replay; changed canonical bytes409. Provider/read-only reconciliation uses exact configured API account/known public ID and constructed untransformed CDN URL, bounded bodies, no redirect/retry, independent metadata and SHA256 matching. Failed/unused resources are retained; no delete/cleanup timer. Reconciliation does not imply an absent resource is safe to overwrite.
