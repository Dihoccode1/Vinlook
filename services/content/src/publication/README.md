# Review and publication

Approved TASK013 contract: docs/planning/task013-review-publication-contract.md. Review/submit/return/publish routes mount before the TASK012 JSON parser, enforcing their own16KiB limit and60s deadline starting before fresh Identity authorization. Existing admin GET reloads state after409. Staff cannot return/publish; self-review is allowed. Only drafts are reviewed; return unlocks in_review for edits.

`createPublicationService(runtime)` snapshots a trusted `publicationRegistry` manifest with exactly16 language/model entries. This slice adds no production environment loader and selects no real model. Runtime without that explicitly approved manifest or media verifiers fails503 for approve/submit/publish. Reject/return and existing operations remain available. The actual job/registry integration is a later gate; tests inject an explicitly synthetic manifest.

Read-only thumbnail/audio provider verification precedes the transaction, with remaining deadline and AbortSignal propagated to the existing media verifier. The service rechecks the complete revision/parent/localized snapshot inside the transaction, increments actual parent/revision counters and writes outbox atomically. MongoDB's withTransaction timeout owns transaction operation budgets; per-operation timeoutMS is used only outside the transaction. No network provider call occurs inside a transaction.

Publish reuses revision.publish replay, including a concurrent-completion check. Fresh authority still applies to replay, which returns the original minimal result without provider calls. A different key cannot republish a published revision. Published historical graphs are retained; public delivery remains TASK014. The Manager's required confirmGeography attests human checking, not automated polygon/entrance verification. No successful API call demonstrates pronunciation, real provider availability, hosting readiness or actual geography correctness.

Tests: npm run test:publication (4groups); npm run test:publication:db requires a fresh task-labelled/pinned loopback replica set matching the strict guards in the integration test. Never use a real URI or existing shared database. See the implementation evidence for exact runs and remaining acceptance gates.
