# TASK016 durable job protocol

User-approved contract: docs/planning/task016-job-protocol-contract.md. Owner Duy, human reviewer Tú. This module implements staff Process/Retry/status, scoped claim/renew/result, typed ProcessingJob snapshots/indexes and restricted worker backend audio uploads. It does not implement an actual translation/TTS adapter, Python execution or model selection.

`createJobService(runtime)` snapshots a strict server-owned processingManifest. No ordinary runtime loader for real model identifiers is added here; absent manifest fails503 on new processing/worker actions. Job status reads remain possible with an existing verified catalog. Local caller uses CONTENT_WORKER_ID and canonical32-byte CONTENT_WORKER_KEY_B64URL; optional old key/ISO cutoff lasts no more24h. Keys must differ from Identity/public cursor and each other; no real key is created. Transport HTTPS/ingress configuration and worker deployment are future release gates, not trust in forwarded headers.

Claim matches server-owned execution/capability scope, acquires one job in a Content transaction,5min lease/60s renew and max3automatic reclaims, then failed/manual retry. No background ping/scheduler/broker. Server adapters have a trusted factory-only scope; local-worker HTTP cannot select that execution. Worker polling30s is a later client responsibility, only while actively processing. Reclaim can repeat physical computation and is not an exactly-once provider guarantee.

Input includes immutable source/text snapshot plus destination row version for translation. Late translations cannot overwrite newly edited manual text. Metadata-only edits are permitted; source/text/draft/deletion state is rechecked on admission and inside output transaction, with real parent/revision counter writes. Translation result creates audio only after exact accepted text/version; preserved current good outputs are not regenerated merely for pending review. Completion audit keeps admitted cycle actor/session, even after close; manual retry changes requester/session for that new cycle.

Result receipt hash prevents duplicate output/outbox. Replay accepted attempt returns original receipt even when lease expired/draft later changed; new attempts cannot act on old receipts. Actual result verification60s deadline starts before worker admission/body parsing, reusing the existing bounded deadline middleware; pretransaction queries use remaining budget and transaction operations inherit Mongo driver's deadline. The shared timeout body's safe503 code is PUBLICATION_VERIFICATION_UNAVAILABLE; internal job callers must treat it as dependency timeout, not a claim of publication.

Worker media binds MediaUpload.jobId/attemptId and live snapshot. Reuse existing90s/probe/process-wide slot/independent provider verification. Lease lost during provider upload may leave verified/uncertain unattached bytes; result admission rejects stale attempt. Uncertain state only reconciles, never blindly POSTs again; no cleanup. Existing trusted audio fixture call sites now explicitly supply synthetic attempt IDs. No Atlas/backfill or adoption of preexisting audio records is authorized. Staff thumbnail intent has attemptId null.

Runtime recognizes existing processing_jobs catalog, or requires it when worker credentials enable job runtime. Verification creates/repairs no collection/index.6owned collections without media or7with it; old nonjob catalogs still work. Tests require pinned labelled loopback empty databases, no arbitrary URI. See implementation evidence for actual counts and remaining registry/provider/worker/hosting acceptance. Overall product readiness stays503.
