# TASK-012 draft API integration

Approved routes under /api/v1: POST /admin/pois, POST /admin/pois/:id/draft, PATCH /admin/revisions/:id, PATCH /admin/revisions/:id/languages/:code, GET /admin/pois/:id. Exact shapes and error semantics are in docs/planning/task012-draft-api-contract.md. All call fresh Identity authority; every write requires a current open session. Shared active Staff/Manager workspace, no client-supplied actor/session. Source English is edited only through sourceTextEN. JSON ceiling128KiB, strict request schemas, exact-origin CORS and no-store envelopes.

POST requires canonical UUID Idempotency-Key and reuses TASK-015 atomic replay/outbox executor; revision.draft is the approved additional operation. PATCH is optimistic concurrency, not idempotent response replay: retain unsaved input and reload after409, including a lost-success-response retry. A matching no-op does not bump versions or write an audit event. Every real edit/clone increments POI.mutationVersion in the same transaction, making a real parent write that conflicts with delete. Future delete/restore implementations must conditionally update this same parent/counter; no matching-value/no-op lock is claimed.

Changing English source advances sourceVersion/English textVersion, keeps non-English source/text/audio provenance old and clears all dependent approvals. Explicit same-text locale adoption against a new source advances that locale textVersion and invalidates audio/review. Metadata alone does not change text/audio versions. Published revisions/children and the published pointer are preserved during draft work. No provider job is automatically run. Read DTO includes derived isSourceCurrent/isAudioCurrent; admin reload selects working-language rows when a working revision exists.

Without CONTENT_MONGODB_URI the existing health-only process stays available with readiness503. With it, configure CONTENT_ALLOWED_ORIGINS plus existing IDENTITY_BASE_URL and CONTENT_IDENTITY_SERVICE_KEY_B64URL. Startup reads/verifies the exact five Content collections/indexes and every persisted POI counter, never repairs/creates data/indexes. URI must name vinlook_content (fixture tests vinlook_content_task012). Missing/invalid catalog/counter fails before listening; existing POIs without mutationVersion require a separately reviewed deployment migration. No Atlas migration is included.

Runtime factory opens the verified connection; server starts outbox sender after listening and closes sender/connection on shutdown. Injected fixture runtime may supply a test-only verifier accepting an explicit synthetic asset allowlist. Production has no real TASK-019 Cloudinary verifier yet: nonnull thumbnail submission safely returns503 MEDIA_VERIFICATION_UNAVAILABLE. Clearing with null works; cloning a prior verified reference copies it unchanged for later publication revalidation. Numeric geometry bounds do not prove HCMC membership or entrance safety. No publication/review/jobs/public-read/delete/restore/admin-list API is introduced here. Overall readiness remains503.

Schemas/immutable flags are not protection against raw DB mutation. Product bootstrap must not bypass catalog/data verification; later APIs must preserve parent guard and full publication gates. Fixture tests can create published-looking rows only to test preservation, not to claim an approved real POI or16language publication.
